# Style

## Commit messages

- One line, at most 60 characters, lowercase, imperative: `auth: add change-password endpoint`,
  `posts: fix saved list images`, `docs: update partner setup`.
- Optional prefix: `auth`, `posts`, `profiles`, `admin`, `notifications`, `files`, `ui`, `db`, `tests`, `docs`.
- No body unless it is really needed, and then at most two short lines.
- No bullet lists, milestone codes, issue or decision IDs, test IDs or file lists.

## Code comments

- Comment only when the reason behind the code isn't obvious from the code itself. Usually one short line.
- Don't reference internal documents or IDs (issue numbers, milestones, design sections, test IDs).
- No essays, and don't restate what the code does.
- Short XML doc comments are fine on public service methods where they help.
